### 2026-06-11 P0-01E AK/SK 双 Token、刷新轮换与登出吊销

已完成：
- 后端新增 Flyway migration `V13__auth_refresh_token.sql`，创建 `user_refresh_token` 表。
- Refresh Token（SK）仅保存 SHA-256 哈希，不在数据库保存明文 token。
- 登录和注册接口返回双 token：
  - `accessToken`：短期 AK，用于 `Authorization: Bearer <accessToken>`。
  - `refreshToken`：长期 SK，仅用于刷新 AK。
- 默认时效调整为：
  - AK：`REPOGUARD_AUTH_ACCESS_TOKEN_TTL_SECONDS`，默认 900 秒。
  - 普通 SK：`REPOGUARD_AUTH_REFRESH_TOKEN_TTL_SECONDS`，默认 7200 秒。
  - 记住登录 SK：`REPOGUARD_AUTH_REMEMBER_TOKEN_TTL_SECONDS`，默认 2592000 秒。
- 新增 `POST /api/v1/auth/refresh`：
  - 校验 SK 哈希、状态和过期时间。
  - 刷新成功后吊销旧 SK。
  - 重新签发新 AK 和新 SK，实现 refresh token rotation。
- 新增 `POST /api/v1/auth/logout`：
  - 根据当前 SK 哈希查找会话。
  - 将 SK 标记为 `REVOKED`，避免退出后继续刷新。
- 新增 `POST /api/v1/auth/refresh-token/reset`：
  - 使用账号密码重新校验身份。
  - 吊销该用户已有 ACTIVE SK。
  - 重新签发 AK/SK，用于 SK 过期后的会话重置入口。
- 前端请求封装升级：
  - AK 保存为 `repoguard.accessToken`。
  - SK 保存为 `repoguard.refreshToken`。
  - 未勾选记住登录时保存到 `sessionStorage`。
  - 勾选记住登录时保存到 `localStorage`。
  - 业务接口遇到 401 时自动调用 `/api/v1/auth/refresh`。
  - 刷新成功后自动重试原请求一次。
  - 刷新失败时清理登录态并跳转 `/login`。
- 前端退出登录改为调用后端 `/api/v1/auth/logout` 后再清理本地 token。
- 保留旧 `repoguard.authToken` 的读取/清理兼容，避免旧会话残留影响用户体验。

### 2026-06-11 P0-02B 配置敏感字段重加密工具

已完成：
- 后端新增 `SecretReEncryptionService`，支持扫描并重加密配置表敏感字段。
- 覆盖字段：
  - `integration_config.token_value`：GitHub Token、MySQL 密码、RabbitMQ 密码等集成密钥。
  - `review_policy_config.api_key_value`：LLM API Key。
- 后端新增管理接口 `POST /api/v1/config/secrets/re-encryption`，通过 `@RequireRole("ADMIN")` 限制为管理员访问。
- 重加密请求支持：
  - `sourceEncryptionKey` / `sourceKeyId`：旧密钥信息。
  - `targetEncryptionKey` / `targetKeyId`：新密钥信息。
  - `execute=false`：默认预检，只输出报告，不写数据库。
  - `execute=true`：执行写回。
  - `confirmText=RE-ENCRYPT`：执行写回时必须提供确认短语，避免误操作。
- 重加密报告不会回显任何密钥明文或敏感值，只返回表名、记录 ID、字段名、provider、源格式、源 keyId、目标 keyId、状态和说明。
- 支持处理：
  - 旧 `enc:v2:{oldKeyId}:...` 密文。
  - 旧 `enc:v1:...` 密文。
  - 历史明文敏感值。
  - 已经使用目标 keyId 的密文会跳过。
  - 解密失败的字段会标记为 `FAILED`，不写回。
- `SecretCryptoService` 新增 `encryptedKeyId()` 和 `activeKeyId()`，供重加密报告和目标 key 判断使用。

验证记录：
- `mvn test "-Dtest=SecretReEncryptionServiceTest,SystemConfigControllerTest,SecretCryptoServiceTest"` 通过，25 个重加密/配置/加密相关测试全部成功。
- `mvn test` 后端全量测试通过，157 个测试全部成功。

遗留事项：
- 当前工具通过管理 API 传入旧/新密钥，后续生产环境更推荐改为只从安全环境变量或密钥管理系统读取，避免密钥进入 HTTP 请求链路。
