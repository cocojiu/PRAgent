### 2026-06-10 P1-10A RabbitMQ 发布确认与发送失败短重试

已完成：
- 开启 RabbitMQ publisher confirm：
  - `spring.rabbitmq.publisher-confirm-type=correlated`
- 开启 unroutable message return：
  - `spring.rabbitmq.publisher-returns=true`
  - `spring.rabbitmq.template.mandatory=true`
- `RabbitReviewTaskPublisher` 改为带 `CorrelationData` 发布，并同步等待 broker confirm。
- 发布阶段增加短重试策略：
  - 默认总尝试次数：3 次
  - 默认退避：500ms -> 1500ms
  - 默认 confirm 等待超时：5000ms
- 新增环境变量：
  - `REPOGUARD_REVIEW_PUBLISH_MAX_ATTEMPTS`
  - `REPOGUARD_REVIEW_PUBLISH_INITIAL_INTERVAL_MS`
  - `REPOGUARD_REVIEW_PUBLISH_MULTIPLIER`
  - `REPOGUARD_REVIEW_PUBLISH_CONFIRM_TIMEOUT_MS`
- 发送异常、publisher nack、unroutable return、confirm timeout 都会抛出 `MessagePublishException`，避免任务创建/重试接口静默成功但 MQ 没收到消息。
- 当前 `triggerManualReview` 和 `retryReview` 仍在事务内调用 publisher；发布最终失败会回滚本次入队状态，避免产生不可消费的 `queued` 任务。

验证记录：
- `mvn -Dtest=RabbitReviewTaskPublisherTest,RabbitMqConfigTest,ReviewServiceImplTest test` 通过，22 个测试全部成功。

遗留事项：
- 当前完成的是 HTTP 请求内同步短重试和显式失败，不包含后台补偿扫描。
- 后续可新增 `PUBLISH_FAILED` 状态或发布补偿表，由定时任务对发布失败任务做最多 5-10 次异步补偿，并暴露运维可观测指标。

### 2026-06-10 P1-10C RabbitMQ 发布补偿 claim/lease 机制

已完成：
- 新增 Flyway migration `V11__review_task_publish_claim.sql`。
- `review_task` 新增补偿抢占字段：
  - `publish_claimed_at`
  - `publish_claimed_by`
  - `idx_review_task_publish_claim(status, publish_claimed_at)`
- `ReviewTaskPublishCompensator` 在补偿发布前先执行数据库条件 claim：
  - `status = PUBLISH_FAILED`
  - `next_publish_retry_at <= now`
  - `publish_attempts < maxAttempts`
  - `publish_claimed_at is null` 或 claim 已超过 lease 时间
- 只有 claim 成功的实例才会执行 MQ 重新发布，避免多实例重复补偿同一任务。
- 发布成功或失败后都会清空 claim 字段，失败时刷新下次补偿时间。
- 新增环境变量：
  - `REPOGUARD_REVIEW_PUBLISH_COMPENSATION_LEASE_MS`
- 默认 lease 时间为 120000ms。

验证记录：
- `mvn -Dtest=ReviewTaskPublishCompensatorTest,RabbitMqConfigTest test` 通过，7 个测试全部成功。

遗留事项：
- 后续建议将 `publish_claimed_by` 暴露到运维诊断或日志中，便于定位多实例补偿归属。
- 后续可继续补充 `PUBLISH_FAILED` 数量、claim 超时次数、补偿成功/失败次数等指标。
