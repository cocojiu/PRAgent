# 2026-06-14 优化进度记录

### 2026-06-14 P3-02D 大 PR 分片审查与聚合摘要

已完成：
- 新增 `PullRequestDiffChunker`，根据文件数量、增删行规模和敏感路径判断是否需要分片，避免大 diff 一次性塞入 LLM 导致上下文截断。
- 分片排序优先覆盖数据库迁移、认证权限、运行配置、构建发布链路等高风险文件，保证关键变更优先进入审查上下文。
- LLM reviewer 接入分片审查：小 PR 保持原单次审查路径，大 PR 或敏感多文件变更会逐 chunk 调用 LLM。
- 聚合所有分片 findings，并以最高分片风险作为 PR 级风险等级，任务仍保持原有 findings 入库和人工审查门禁流程。
- LLM prompt 摘要记录 `chunked=true`、分片数量、聚合风险、聚合 finding 数和分片原因，便于详情页和后续质量分析追踪。
- 补充分片器测试和 LLM 分片聚合测试，覆盖敏感文件优先、完整文件覆盖、小 PR 不分片、多分片聚合风险等场景。

验证记录：
- `mvn "-Dtest=LlmPullRequestReviewerTest,PullRequestDiffChunkerTest,ReviewTaskExecutorImplTest" test` 通过，11 个 LLM reviewer、分片器和任务执行器用例全部成功。

遗留事项：
- 当前分片阈值为代码内置常量，后续可暴露到系统策略配置，支持按仓库或分支调整。
- 当前分片聚合摘要主要记录在 LLM prompt 摘要字段，后续可扩展独立字段或详情卡片，展示每个 chunk 的风险和 finding 分布。
- 当前多分片中任一 LLM 调用失败会整体走规则兜底，后续可做部分分片失败重试或混合聚合。

### 2026-06-14 P3-02F PR 总评自动生成与 GitHub PR 总评回写

已完成：
- 后端新增 `PrReviewSummaryDto`，基于 PR 风险画像、findings、缺失测试建议和变更文件自动生成 PR 级总评。
- 审查详情接口新增 `prSummary`，返回综合风险、摘要、合并建议、是否建议合并、是否需要人工复核、关键风险和重点文件。
- GitHub 评论预览新增 PR 总评草稿，作为 `pull_request` 级评论展示在 findings 评论之前。
- GitHub 回写流程支持 PR 总评评论发布，复用现有发布批次、失败摘要、历史记录和人工门禁能力。
- 新增 `V22__github_pr_summary_comments.sql`，允许 GitHub 评论发布表和批次明细表的 `finding_id` 为空，用于表示 PR 级总评评论，避免虚拟 finding 破坏外键语义。
- 前端审查详情页在审查摘要卡展示 PR 总评、合并建议、关键风险和重点文件；评论预览支持 `findingId=null` 的 PR 总评草稿。

验证记录：

- `node node_modules/vite/bin/vite.js build` 前端生产构建通过。

遗留事项：

- 下一步建议实现 Finding 去重与合并，降低大 PR 分片审查带来的重复结果。

### 2026-06-14 P3-02G Finding 去重与合并

已完成：
- 审查执行器在 findings 入库前按 `filePath + lineNumber + message` 做基础去重，覆盖 LLM 分片聚合和规则兜底输出。
- 重复 finding 合并为一条，保留更高严重级别，来源、规则 ID 和修复建议做轻量合并，避免重复评论干扰 reviewer。
- 去重逻辑位于 worker 持久化边界，不影响 LLM reviewer、规则 reviewer 和前端查询模型。
- 补充 `ReviewTaskExecutorImplTest`，覆盖重复 finding 只入库一次、严重级别取更高值、来源/规则/建议合并。

验证记录：
- `mvn "-Dtest=ReviewTaskExecutorImplTest,ReviewServiceImplTest,ReviewControllerTest,ApiContractTest" test` 通过，53 个执行器、审查服务、控制器和契约用例全部成功。

遗留事项：
- 当前去重为精确 key 匹配，尚未做语义相似度合并。
- 当前合并信息写入原有 source/ruleId/recommendation 字段，后续如需更精细展示可增加独立合并元数据。
- 下一步建议推进“规则 + LLM 混合审查”，让确定性规则和 LLM 语义审查同时参与，而不是仅在 LLM 失败时规则兜底。

### 2026-06-14 P3-02H 规则 + LLM 混合审查

已完成：
- LLM 审查和规则审查不再是单纯失败兜底关系，规则 findings 可以与 LLM findings 一起进入结果集合。
- LLM findings 负责语义风险补充，规则 findings 负责确定性底线检查，最终由执行器统一去重、合并和入库。
- 原有人工审查门禁、PR 风险画像、PR 总评和 GitHub 回写复用合并后的 findings，不额外引入一套展示模型。
- 补充 LLM reviewer 和任务执行器测试，覆盖混合输出和规则结果参与聚合的场景。
