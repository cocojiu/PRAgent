# 优化进度记录

本目录从 ../05-企业级线上项目优化方案.md 的原第 15 节拆分而来，用于按日期维护实施进度，降低主方案文档体积和上下文读取成本。

## 15. 优化进度记录

### 15.1 优化进度记录规则

- 每完成一项优化，必须同步更新本章节的优化进度记录，不得仅修改代码而不更新文档。
- 每项记录至少应包含：优化日期、优化编号或名称、已完成内容、验证记录、阶段结论及下一步建议或遗留事项。
- 只有相关测试、类型检查或构建验证通过后，才能将该项标记为“已完成”；尚未验证或验证失败的事项应明确标记为“进行中”或“阻塞”。
- 文档中的验证记录必须如实注明执行的命令、测试范围和结果；因依赖、网络或环境限制无法验证时，应记录具体阻塞原因。
- 优化进度文档应与对应代码变更同步更新、定向 stage 和提交，避免文档进度与仓库实际状态不一致。
- 如果优化调整了原定优先级、架构边界或后续路线，应同时更新本方案中的相关结论和下一步建议。
